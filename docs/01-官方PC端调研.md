# 《明日方舟》官方 PC 端调研

> 调研日期：2026-11-20。资料来自官方公告、MAA 源码/发布说明/issue、MaaFramework 源码、
> 社区实测，以及**本机实测**（本机已安装鹰角启动器 1.6.0 与 MAA v6.22.0）。
> 标注：高=官方或源码直证；中=单一来源/需推断；低=未证实。

## 1. 结论摘要

1. 官方 PC 端是**原生 Windows 版 Unity 游戏**（Unity 2021.3.39f1 + IL2CPP x86_64），
   不是安卓容器、不是云游戏，**没有 ADB、没有端口、没有 adb.exe**。【高】
2. 它带腾讯 ACE 反作弊（内核驱动 `ACE-BASE.sys` / `ACE-CORE.sys` + 进程内 `ACE-Base64.dll`，
   本机 `games\Arknights\AntiCheatExpert\` 可见），并对游戏进程做完整性保护。【高】
3. MAA 从 **v6.3.0** 起支持 PC 端，走的是 **Win32 窗口绑定**：
   `AsstAsyncAttachWindow(hwnd, screencap_method, mouse_method, keyboard_method)`，
   底层是 `MaaWin32ControlUnit.dll`（PrintWindow/WGC/DXGI 截图 + 消息/合成触控注入），
   官方定性为"社区维护、不保证可用性"。【高】
4. 官方 PC 端的窗口标题是 **「明日方舟」**（外服按客户端类型不同），主进程 `Arknights.exe`；
   启动器进程 `Games.exe` / `Launcher.exe`（Qt5 + QCefView + CEF）。【高/中】
5. 2026 年 10-11 月更新后，游戏**必须由启动器作为父进程拉起**，直接启动 `Arknights.exe` 会被强退。
   ⇒ "自动启动"必须启动启动器，而不是直启游戏 exe。【中，社区实测】
6. 硬性画面契约：**16:9**（推荐 1280×720 / 1920×1080）、游戏内 **UI 缩放 100%**、
   鼠标指针比例调小；分辨率设置存在 `HKCU\Software\Hypergryph\Arknights`。【高】
7. 两个 PC 端特有的坑：**鼠标视差**（UI 随鼠标位置偏移，MAA 会在识别主界面前把光标移到窗口中心
   等 300ms）与**异步输入丢事件**（PostMessage/AnchoredTouch 在高负载下会丢）。【高】

## 3. 官方 PC 端 vs MuMu 模拟器 12

| 维度 | 官方 PC 端 | MuMu 12 |
|---|---|---|
| 运行层 | 原生 x86_64 Unity/IL2CPP | Android VM + ARM 翻译 |
| 进程 | `Games.exe`(启动器) / `Arknights.exe`(游戏) | `MuMuPlayer` / `MuMuNxDevice` + 客户机游戏 |
| 连接 | **HWND 绑定，无端口** | ADB `127.0.0.1:16384 + 32n` |
| 截图 | PrintWindow / WGC(FramePool) / DXGI / ScreenDC / GDI | `adb screencap` 或 `external_renderer_ipc.dll` |
| 输入 | Send/PostMessage（带 CursorPos/WindowPos 变体）、AnchoredTouch、Seize、Interception | minitouch / MaaTouch / adb input / MuMu SDK |
| 坐标 | 客户区像素 1:1、无旋转 | 需 `max_x/max_y` 换算 + 查 SurfaceOrientation |
| 后台 | PrintWindow/WGC 可后台（伪最小化）；WindowPos 会把窗口移出屏幕 | 截图增强可后台 |
| 特有坑 | 鼠标视差、公告独立窗口截不到、异步丢事件、必须启动器拉起、需管理员 | 端口、SELinux、渲染色差 |
| 反作弊 | ACE 内核 + 进程内 Detours + TVM | ACE `libtersafe2.so` |

**本质差异**：模拟器是"adb 命令 → 安卓输入系统"；PC 端是"Win32 消息 → Unity 输入"。
坐标从"逻辑分辨率 → 设备像素"的一次换算，变成"客户区像素"的直通，但多了**鼠标位置**这一真实状态。

## 4. MAA 的 Win32 控制单元（复刻依据）

MaaFramework `source/MaaWin32ControlUnit/`：

- 截图方法：`GDI(1)`、`FramePool/WGC(2)`、`DXGI_DesktopDup(4)`、`DXGI_DesktopDup_Window(8)`、
  `PrintWindow(16)`、`ScreenDC(32)`。
- 输入方法：`Seize(1)`、`SendMessage(2)`、`PostMessage(4)`、`LegacyEvent(8)`、
  `SendMessageWithCursorPos(32)`、`PostMessageWithCursorPos(64)`、
  `SendMessageWithWindowPos(128)`、`PostMessageWithWindowPos(256)`、`Interception(512)`、`AnchoredTouch(1024)`。
- **PrintWindow 实现**（`Screencap/PrintWindowScreencap.cpp`）：
  `GetClientRect` → `CreateCompatibleBitmap` → `PrintWindow(hwnd, dc, PW_CLIENTONLY | PW_RENDERFULLCONTENT)`
  → `GetDIBits` 取 32bpp BGRA；若存在活动弹窗，再截弹窗并按客户区偏移叠加。
- **MessageInput 实现**（`Input/MessageInput.cpp`）：
  `WM_ACTIVATE(WA_ACTIVE)` → 10 ms → `SetCursorPos(ClientToScreen(x,y))`（CursorPos 模式）
  → `WM_MOUSEMOVE(MK_LBUTTON)` → 10 ms → `WM_LBUTTONDOWN` →（拖动时若干 `WM_MOUSEMOVE`）→ `WM_LBUTTONUP`。
  `lParam = MAKELPARAM(客户区x, 客户区y)`；手势期间可 `BlockInput`，结束后恢复光标位置。
- **视差处理**：MAA 的 `Win32Controller::screencap_impl` 在识别主界面前把鼠标移到窗口中心并等 300 ms；
  本项目的设备层采用同一思路（固定"停靠点" + `parallax_wait`）。

本项目 `src/garrison_pc/device/win32.py` 即按上述协议实现，并额外做了：
黑图自动回退（printwindow → gdi → screendc）、弹窗合成、非 16:9 居中映射、
最小化检测、截图尺寸校验、点击前 `WM_ACTIVATE`、手势后光标归位。

## 5. 风险与限制（必须在文档/程序里提示用户）

| 风险 | 说明 | 本项目的处理 |
|---|---|---|
| ACE 反作弊 | 修改二进制/注入 DLL 风险极高；消息注入目前无公开封号案例，但官方未承诺 | 只做**外部输入注入**，不注入进程、不改内存/文件 |
| 启动器父进程校验 | 直启 `Arknights.exe` 会被强退 | 默认通过鹰角启动器拉起；也可让用户手动开好游戏 |
| 鼠标视差 | 鼠标位置会改变 UI 位置 | 固定停靠点 + 截图前等待；停靠点可配置 |
| 公告窗口 | 独立顶层窗口，主窗口截图截不到 | 设备层捕获活动弹窗并合成；仍失败时按"未知界面"重试 |
| 异步丢事件 | PostMessage 在高负载下可能丢 | 每步留 10~15 ms、点击保持 45 ms、拖拽分步；失败重试 |
| 最小化 | PrintWindow 对最小化窗口不可靠 | 检测到最小化直接报错并提示恢复窗口 |
| 管理员权限 | 跨权限级窗口的消息可能被 UIPI 拦 | 自检失败时提示"以管理员身份运行" |
| 窗口被遮挡 | PrintWindow 可后台，但 DXGI/ScreenDC 不行 | 默认 printwindow，自动回退并记录实际方式 |
| 登录/掉线 | PC 端扫码登录，日更/公告会回登录界面 | 30 秒离场保护 + 日志/截图 + 提示回主界面重跑 |
| 多开/多账号 | 官方无多开；绑定一个 HWND | 只支持单实例；`--list-windows` 辅助排查 |

## 6. 对自动化方案的影响

1. 不能设计 ADB 路径（PC 端没有），抽象必须是 **窗口句柄 + 截图方式 + 输入方式**。
2. 坐标系必须按**窗口客户区像素**，并且要处理 DPI（Per-Monitor V2）与 16:9 契约。
3. "鼠标"是真实状态：截图前要停靠、点击要移动真实光标；这与模拟器上"发个 tap 就行"完全不同。
4. 启动/退出要走启动器：启动 = 调启动器；退出 = 不主动杀进程（避免误杀/触发反作弊）。
5. 复用 MAA 的配置与 PaddleOCR 模型是最省事、最稳定的做法（MAA 的模型随版本升级）。
