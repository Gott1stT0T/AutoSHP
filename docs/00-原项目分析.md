### 1.2 复原方法（为什么必须复原）

原项目只发布 exe，业务逻辑（选策略、买干员、升级商店、布阵、判定角标）全部在冻结的字节码里。
要适配官方 PC 端，必须先看清它"怎么操作设备、怎么决策"。

采用的办法：

1. **拆 PyInstaller 包**：解析可执行文件尾部的 CArchive cookie，按 TOC 取出主脚本条目；
   条目是 zlib 压缩的 marshal 数据，解压后得到 CPython 3.11 的 module code object。
   （工具：`_tools/pyi_extract.py`、`_tools/split_funcs.py`，仅用于分析，不随交付。）
2. **按函数转储**：把 module 的 75 个 code object（含推导式/嵌套函数）逐个导出为
   "常量表 + 完整字节码"的规格文件（`_ref/funcs/*.txt`）。
3. **建立 oracle**：在 Python 3.11 下用桩模块 `exec` 原始 code object，
   得到一个**可调用的原版模块**（常量与函数都在），用于差分测试。
4. **逐函数还原 + 差分验证**：见第 7 节。

> 结论：原程序 = 一份约 1300 行的单体 Python 脚本（`garrison_farm.py`）
> ＋ 一个运行期插件接缝（`mumu_touch.py`）。

### 2.3 主循环状态机（还原后的等价伪代码）

```text
启动自检（写权限 / 文件 / MAA / 连接设置 / 连接设备 / 截图 / 拖拽支持 / OCR 模型）
  ↓ 任一致命项 → 弹窗退出
提示"使用前提醒"（自选编队 / 权重名单 / 点击确定）
  ↓
检测 3 次：画面里是否有「极速模拟」或「断线重连」；没有 → 提示回主界面退出
  ↓
while 通关数 < 目标:
    img = 截图; items = OCR(img); txt = 拼接文本
    ├ 超过 STALL_TIMEOUT 无进展 → 存图、退出
    ├ 30 秒内没出现 GARRISON 关键词 → 存图、退出（掉线保护）
    ├ 「点击取消」+「准备就绪」→ 补设朝向（LAST_TILE）或点取消
    ├ 「返回主页」→ 判定「模拟完成」→ 记录/存进度/统计 → 点返回主页 → 新 Board
    ├ 「请选择模拟难度」或「开始模拟+极速模拟+回合」→ 点开始模拟
    ├ 「确认准备」/「资金将在」→ 点(860,602) + (1410,728)
    ├ 「断线重连」→ 点重连
    ├ 「独立模拟」+「极速模拟」→ 点极速模拟
    ├ 「确认本局信息」→ 点(1686,986)
    ├ 「选择策略」→ pick_strategy(done) → 点(1680,990)
    ├ 「确定自选编队」→ pick_squad()
    ├ 「回合」+「准备就绪」+(刷新|升级|满级) → prep_phase(board, img)
    ├ 「回合」/(查看+极速模拟)/COUNTDOWN → 标记休整、等 4 秒
    └ 其它 → GARRISON 命中时点 GENERIC 文案；否则每 5 次存一张 unknown 图、等 2 秒
```

`prep_phase` 是单局核心：读金币与商店 → 升级商店（前 4~5 回合）→ 满级后只买 5/6 级 →
按权重购买 → 备战席拖到最右 3 列（安全位优先给远程）→ 位子不够就卖最低星 → 处理晋升/弹窗。

## 3. 与 MuMu 模拟器的耦合点（改造的关键）

逐条列出"哪些地方假定自己在操作一个安卓模拟器"：

### 3.1 设备发现：MAA 配置 + 安卓端口

- 从 MAA 的 `config/gui.new.json`（v6.15+）或 `config/gui.json` 读 `AdbPath` 与 `Address`；
  找不到再用 `adb devices` 的**唯一在线设备**，再退化为常见模拟器端口表：

```python
COMMON_ADDRS = ['127.0.0.1:16384', '127.0.0.1:16416', ... '127.0.0.1:7555', ...]
EMU_PROCS = ['MuMuNxDevice', 'MuMuPlayer', 'MuMuNxMain', 'dnplayer', 'LDPlayer', ...]
```

- 端口假设：MuMu 12 的 ADB 端口 = `16384 + 32 × 实例号`。

### 3.2 截图：`adb exec-out screencap -p`

```python
def shot():
    for _ in range(5):
        raw = adb('exec-out', 'screencap', '-p', capture=True)
        img = cv2.imdecode(np.frombuffer(raw, np.uint8), cv2.IMREAD_COLOR)
        if img is not None:
            return img
        time.sleep(0.5)
    raise RuntimeError('截图失败')
```

自检里还硬校验 `(1920, 1080)`，不符只提示不阻断。

### 3.3 触控：`adb shell input`

```python
def tap(x, y, wait=0.6):  adb('shell', 'input', 'tap', str(int(x)), str(int(y))); time.sleep(wait)
def swipe(...):           adb('shell', 'input', 'swipe', ...)
def touch(kind, x, y):    adb('shell', 'input', 'motionevent', kind, str(int(x)), str(int(y)))
```

`motionevent` 需要 Android 12+ 的 `input` 支持（MuMu 12 满足），自检里会试发一次
`input motionevent` 并检测返回，失败则提示"请使用安卓 12 的模拟器"。

### 3.4 拖拽：把多段 `motionevent` 拼进**一条** adb shell 命令

```python
def drag_path(x1, y1, x2, y2, steps=12):
    cmds = [f'input motionevent MOVE {int(...)} {int(...)}' for k in range(1, steps+1)]
    adb('shell', '; '.join(cmds))
```

这是为 ADB 做的性能优化（一次进程调用发完所有 MOVE）。**移植时必须换成设备原语**。

### 3.5 MuMu SDK 增强（`mumu_touch.py`，个人优化版新增）

- 加载 `nx_main/sdk/external_renderer_ipc.dll`（或 `nx_device/<ver>/shell/sdk/`）。
- 用 `nemu_connect(root, instance_index)` 连接实例；`nemu_get_display_id(handle, package, 0)`
  找游戏画面（官服 `com.hypergryph.arknights` / B 服 `.bilibili`）。
- `nemu_capture_display(...)` 直接拿 RGBA 帧，翻转为 BGR，**替代 ADB 截图**。
- `nemu_input_event_finger_touch_down/up` 直接注入触控，**替代 ADB input**。
- 实例号由 ADB 端口反推：`(port - 16384) // 32`。
- 把 `tap/swipe/touch/drag_path` 四个全局函数整体替换，并替换 `shot`。

### 3.6 插件接缝的确切位置（决定了"能不能直接复用"）

原始 `setup(args)` 在个人优化版里被包了一层：

```python
def setup(args):
    result = <原版 setup>(args)          # ← 先做完整自检：找 adb、连设备、截图、装 OCR
    ns = {'__name__': 'garrison_mumu_touch', '__file__': path}
    exec(compile(open('mumu_touch.py').read(), path, 'exec'), ns)
    ns['install'](globals())             # ← 之后才替换触控/截图
    return result
```

**关键结论**：增强模块是在"原版自检通过之后"才加载的；而原版自检强依赖 ADB
（`find_adb` → `adb devices` → `exec-out screencap` → `input motionevent` 探测）。
官方 PC 端没有 ADB，所以**这条接缝在 PC 端走不通**——必须替换自检与设备层本身。
（这也是选择"移植源码"而不是"外挂一个 mumu_touch.py"的直接原因。）

### 3.7 其它耦合

- **分辨率**：所有坐标按 1920×1080；竖屏未实现。
- **客户端**：只支持国服中文；官服/B 服用 `pm list packages` + 前台 Activity 区分。
- **包名/进程**：`EMU_PROCS` 用于从运行中的模拟器进程反推安装目录（给 SDK 用）。

1. **全部业务逻辑**（约 1300 行）：策略挑选、编队、商店、布阵、角标进度、超时保护。
2. **数值与文案**：权重表、安全位名单、坐标表、界面关键词——与原版逐字一致。
3. **`tiles.json`**：拖拽视角下的 8 个格子与升降台坐标。
4. **MAA 复用方式**：只读 MAA 配置 + 使用 `resource/PaddleOCR` 模型，不修改 MAA。
5. **工程经验**：自检清单、`farm_logs/run.log` + 关键截图、30 秒离场保护、

## 5. 原项目的局限

| 局限 | 影响 |
|---|---|
| 逻辑在冻结字节码里 | 无法维护、无法改坐标、无法适配新分辨率 |
| 硬编码 1920×1080 | PC 端窗口尺寸不同就全错位 |
| 依赖 UI 文案与固定坐标 | 活动/版本更新后需要重新校准 |

| 只支持国服 | 外服界面不同 |
| 单文件单体脚本 | 无测试、无分层，稳定性靠"重试 + 超时" |

## 6. 复原质量与验证结果

- **常量**：31 个模块级常量与 oracle 完全一致。
- **纯函数**：`rank/prio_index/is_safe_op/match_key/is_healer/is_dps/tile_order/tile_xy/near/
  shop_signature/find/passed_count/set_profile` 差分测试 **3754 项，0 失败**
  （唯一差异是 v1.2 有意修改的 `passed_count` 语义，见下）。
- **图像函数**：`yellow_ratio/has_badge/has_color_badge/grid_shift/detect_rows/green_tiles/
  right3/is_green/slots_left/locate_new/new_bench_slot/in_facing_mode/bench_ops/drag_name`
  在 14 张随机/构造图上 **330 项，0 失败**。
- **主循环**：用脚本化假设备 + 假 OCR 跑通"主界面 → 开始模拟 → 选策略 → 编队 →
  回合准备（读商店/刷新）→ 结算 → 结束"全流程（`tests/test_farm_loop_mock.py`）。
- **有意的行为差异**（保留个人优化版 v1.2，而不是原版）：

| 函数 | 原版 | v1.2（本项目采用） |
|---|---|---|
| `passed_count` | `已通过` 无数字时返回 1；`①`/全角数字会抛异常或读错 | 返回 `None` 触发重试；统一转普通数字、支持被 OCR 拆分的次数 |
| `pick_strategy` | 先看角标颜色 | 只按"已通过次数 ≥ 目标"跳过；名称仅用于显示 |
| `save_done` | 原样写入 | 过滤 `无法识别名称[...]` 占位名 |
| `drag_path` | 一条 adb 命令发多个 MOVE | 改为逐点 `touch('MOVE')`，由设备层控制节拍（PC 端必需） |
| `deploy_bench` | 固定扫描点 `BENCH_ROWS`，逐行、每行连续 2 个空位就换行 | 先用 `bench_positions()` 按等阶徽章识别实际位置（失败回退 `BENCH_ROWS`），最多尝试 6 次、连续 3 次失败才停 |
