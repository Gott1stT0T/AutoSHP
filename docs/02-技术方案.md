# 技术方案：从 MuMu 插件到官方 PC 启动器

## 1. 方案选择：重写宿主 + 移植业务逻辑（而不是改原 exe / 外挂 mumu_touch）

| 方案 | 可行性 | 结论 |
|---|---|---|
| A. 只替换 `mumu_touch.py`（沿用原 exe） | **不可行**。原 `setup()` 先做 ADB 自检（找 adb → `adb devices` → `screencap` → `input motionevent`），通过后才 `exec` 加载增强模块；PC 端没有 ADB，自检阶段就退出，接缝根本走不到 | 否决 |
| B. 给原 exe 伪造一个 adb.exe（桥接层） | 理论可行，但需要反向适配原程序的全部 adb 调用、依赖 69 MB 第三方冻结包、逻辑仍不可维护、活动更新即报废 | 否决 |
| C. 反编译 + 重写宿主 + 移植业务逻辑 | 业务逻辑可逐函数还原，并有 oracle 差分测试兜底；设备层可完全重写为 Win32；可维护、可测试、可打包 | **采用** |

选择 C 的三条理由：

1. **技术必然性**：PC 端无 ADB，原程序的设备层与自检必须整体替换，这不是"替换一个文件"能解决的。
2. **功能完整性**：只有把 1300 行业务逻辑（选策略/编队/商店/布阵/进度/保护）搬过来，
   才能保证"不只是能启动游戏"，而是真的把角标刷出来。
3. **可维护性**：字节码不可维护；还原成源码后，活动改坐标、改文案、改分辨率都能改。

## 2. 总体架构

```
GarrisonFarmPC
├─ 启动入口 app.py           参数解析 / 模式菜单 / 使用前提醒 / 主循环 / 退出码
├─ 自检 selfcheck.py         目录可写、MAA、连接、截图、输入方式、OCR（✔/⚠/✘）
├─ MAA 集成 maa.py           找 MAA、读 gui.new.json（兼容 gui.json）、
│                            连接配置/ClientType/Win32Extra/PcClientPath、PaddleOCR 模型、
│                            找鹰角启动器、进程探测（MAA 是否在跑 / 游戏是否在跑）
├─ OCR ocr.py                用 MAA 的 PP-OCRv6 det+rec+keys 建 RapidOCR 引擎
├─ 运行时 runtime.py         把设备/日志/截图/进度注入业务层
├─ 设备层 device/
│   ├─ win32.py              官方 PC 端：PrintWindow 截图 + Win32 消息注入（默认）
│   └─ adb.py                模拟器：screencap + input（保留原项目能力）
└─ 业务逻辑 logic/garrison.py 逐函数还原的 1920×1080 逻辑（由 parts/ 组装）
```

数据流：

```
shot()  ──► PrintWindow/截图 → (可选弹窗合成) → 缩放到 1920×1080 → BGR ndarray
   │
OCR     ──► MAA PaddleOCR(det+rec) → [(cx, cy, text)]
   │
决策    ──► 主循环文案匹配 / pick_strategy / prep_phase / deploy_layout ...
   │
tap/swipe/touch ──► 虚拟坐标 → 客户区像素 → SetCursorPos + PostMessage(down/move/up) → 光标归位
```

## 3. 关键设计

### 3.1 虚拟屏幕（1920×1080）与坐标映射

- 业务逻辑全部按 1920×1080 编写（与原程序一致），设备层负责双向映射：
  `client_x = off_x + x * (content_w/1920)`。
- 客户区非 16:9 时按比例**居中留边**（默认），避免拉伸导致全部坐标漂移；
  游戏本身只允许 16:9，正常窗口下映射是纯缩放。
- 截图缩放：缩小用 `INTER_AREA`、放大用 `INTER_LINEAR`，保证 OCR 输入稳定。

### 3.2 截图（对齐 MaaFramework 的 PrintWindow）

```python
GetClientRect(hwnd) → CreateCompatibleBitmap
PrintWindow(hwnd, dc, PW_CLIENTONLY | PW_RENDERFULLCONTENT)
GetDIBits(32bpp, top-down) → ndarray[..., :3]  # BGR
```

增强：
- **弹窗合成**：`GetAncestor(GA_ROOTOWNER)` → `GetLastActivePopup` → 单独截弹窗 →
  按 `ClientToScreen` 偏移贴到主画面（公告/确认框是独立顶层窗口）。
- **黑图回退**：printwindow 失败/纯黑 → gdi(BitBlt) → screendc(桌面 DC)；
  成功后记住可用方式，日志记录实际使用的方法。
- **最小化检测**：`IsIconic` 直接报错，提示"可以后台/被遮挡，但不要最小化"。

### 3.3 输入（对齐 MaaFramework 的 PostMessageWithCursorPos）

游戏"只认真实鼠标位置"，所以点击必须移动真实光标：

```
WM_ACTIVATE(WA_ACTIVE) → 10ms
SetCursorPos(ClientToScreen(x, y)) → 4ms
WM_MOUSEMOVE(MK_LBUTTON, LPARAM(x,y)) → 10ms
WM_LBUTTONDOWN(MK_LBUTTON, LPARAM(x,y)) → 45ms
WM_LBUTTONUP(0, LPARAM(x,y))
→ 光标回到停靠点
```

- 拖拽：`DOWN → MOVE ×N（每步 8~40ms）→ UP`，步数与时长由 `ms` 决定。
- `block_input=True` 时手势期间 `BlockInput(TRUE)`（默认关闭，避免影响用户正常用键鼠；
  开启后运行期间物理鼠标会被锁住）。
- 输入方式可切：`cursor`（默认，真实光标 + PostMessage）/ `post`（纯消息，部分场景无效）/ `send`。

### 3.4 鼠标视差

PC 端 UI 会随鼠标位置轻微偏移，这会让 OCR/像素判定的坐标漂移。
处理：**固定停靠点**（默认客户区中心，即虚拟坐标 960,540），
每次截图前确认光标在停靠点，且距上次移动 ≥ `parallax_wait`（默认 0.20 s）再截图；
点击/拖拽结束后立刻把光标移回停靠点（业务层本身的 `wait` 正好覆盖动画时间）。
停靠点与等待时间都可配置。

### 3.5 MAA 集成（"插件"的边界）

MAA 没有官方插件系统（没有插件目录/ABI；"插件"在社区里指独立程序或 MaaFramework 工程）。
因此本项目按参考项目的做法做成**独立程序 + 复用 MAA 资产**：

- 只读 MAA 的 `config/gui.new.json`（v6.15+）或 `config/gui.json`：
  `ConnectSettings.Config/AdbPath/Address`、`Extras.Win32Extra`、
  `RuntimeSettings.ClientType`、`StartUpSettings.PcClientPath`；
- 只读 `resource/PaddleOCR`（PP-OCRv6 det+rec + keys）作为识别模型；
- 不写 MAA 目录、不注入 MAA 进程、不与 MAA 抢 adb server；
- 检测到 MAA 正在运行时提示"不要同时跑 MAA 任务"（两者会抢操作）；
- 兼容 MAA v5.x~v6.x 的配置位置差异（`Configurations.<Current>.Gui.ConnectSettings` 等）。

### 3.6 启动 / 停止

- 找不到游戏窗口且 `auto_launch=true`：定位鹰角启动器（注册表 `鹰角启动器` 的 InstallLocation、
  MAA 的 `PcClientPath` 上级目录、常见 `Launcher.exe`/`Games.exe`），启动它并等待窗口（默认 180 s）。
- 不主动杀游戏进程（避免误杀/触发 ACE 行为）。
- `Ctrl+C` / 关闭窗口即停止；`device.close()` 会确保松开鼠标、解除 BlockInput。

### 3.7 稳定性与异常处理

| 机制 | 说明 |
|---|---|
| 启动自检 | 8 项检查，分 `✔/⚠/✘`；致命项弹窗说明并退出（退出码 2~5） |
| 离场保护 | 30 秒检测不到卫戍协议关键词 → 存 `left_garrison.png` 并停止 |
| 卡死保护 | 10 分钟无进展 → 存 `stalled.png` 并停止 |
| 未知界面 | 每 5 次存 `unknown.png`，日志可回溯 |
| 读不到数字 | `read_gold`/`numrec` 重试 3 次，失败按"未知"继续（买不起时游戏会提示） |
| 单实例 | 命名互斥体 `Local\GarrisonFarmPC.SingleInstance`，第二个实例直接提示退出（退出码 7） |
| 路径兼容 | 中文路径：截图用 `imencode` 写盘；OCR 模型必要时复制到 ASCII 临时目录 |
| DPI | 线程级 Per-Monitor V2，保证客户区/消息坐标都是物理像素 |
| 日志 | `farm_logs/run.log`（带日期）、关键节点自动截图 |
| 退出码 | 0 正常；1 运行异常；2 无 OCR 模型；3 无设备；4 自检致命项；5 不在卫戍界面 |

## 5. 已知限制

1. **只验证到"设备层 + 主循环 + OCR"**：真正的对局需要账号与活动进行中，
   `--check` 可在实机验证截图/输入，完整刷取需要用户在卫戍协议界面跑一次。
2. **坐标仍按 1920×1080**：PC 端窗口会自动缩放到该虚拟分辨率，但如果游戏 UI 在 PC 端
   有布局差异（如按钮位置/字号不同），需要重新校准文案与坐标（`tiles.json` + 常量）。
3. **只支持国服**（界面文案为简体中文）。
4. **依赖 MAA 的 OCR 模型**：没装 MAA 时可用 `ocr_dir` 指向任意 `PaddleOCR/{det,rec}` 目录。
5. **反作弊**：只做外部输入注入；不保证官方长期允许，风险自负。
