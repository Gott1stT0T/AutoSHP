## 2. 实机联调（官方 PC 端，2026-11-20 下午）

### 2.1 环境与权限（关键结论）

| 现象 | 结论 |
|---|---|
| 中等权限进程 `PrintWindow` 对游戏窗口**返回 0**，`GDI` 只能拿到陈旧的加载 logo | 游戏的 `Arknights.exe` 由 ACE 提升到高完整性级别，低权限进程被 **UIPI** 拦截 |
| 以管理员身份运行后，`PrintWindow(PW_CLIENTONLY\|PW_RENDERFULLCONTENT)` 正常返回 1920×1080 画面 | **必须以管理员身份运行**（程序已实现自动请求提权） |

`tests/_live_integrity.py` 实测：自身 `Medium`，对游戏进程 `OpenProcessToken` 返回
`ERROR_ACCESS_DENIED(5)` → 游戏比本程序权限高。

### 2.2 已验证可用的链路（真实游戏，逐项截图/日志佐证）

1. 定位窗口：标题「明日方舟」、类名 `UnityWndClass`、`Arknights.exe`，客户区 1920×1080（窗口化）。
2. 截图：PrintWindow 成功，1920×1080 BGR，无黑边；`farm_logs/startup_check.png` 为真实游戏画面。
3. OCR：MAA PP-OCRv6 模型在 PC 端中文 UI 上识别准确，单次约 0.6~0.9 s。
4. 输入注入：`SetCursorPos + PostMessage` 点击生效（点开蚀刻章弹窗、点开卡牌详情、点「准备就绪」）。
5. 启动流程：清弹窗 → 识别「极速模拟」→ 进入选难度 → **选择策略**（读到「阿米娅/歌利亚/大帝/卡莱莎 已通过 3 次」并跳过，选中「伊奥莱塔·罗素」）→ **自选编队**（选中 4 名干员）→ 进入对局。
6. 局内：识别回合数、资金、升级费用；**连续升级商店**（0→1→5→8→10，最终升到 V 级）；
   点「准备就绪」；识别结算并统计。
7. 购买与部署：多轮自动运行后，第 5 回合画面里可见 **7 名干员已部署在右侧高台/敌人路径**、
   备战席还有 5 名待部署，商店等级 V、资金 2 —— 说明「买 → 备战席 → 拖拽到格子 → 朝右 →
   点准备就绪」这条链路整体可工作。
8. **拖拽专项验证**（19:02，同一局）：
   - 手动在正确起点按住备战席干员 → 8 个候选格立即变绿（进入拖拽态）→ 移动到目标格 → 松手，
     `PostMessage` 即可触发，**不需要窗口前台**；
   - 调用程序自身的 `deploy_bench()`，一次成功部署 **5 名干员**：
     `慕斯→path0、灰喉→path1、褐果→path2、迷迭香(T5)→safe0、森蚺→rest0`，
     画面上「剩余可放置角色」由 8 变为 3（`farm_logs/run.log` 有对应日志）。
   - 起初几次拖空，原因是固定扫描点 `BENCH_ROWS` 与 PC 端实际站位有偏差；
     已改为先 `bench_positions()` 用等阶徽章识别实际位置、失败再回退固定点。
9. 最终打包程序在真实游戏上 `--check` 通过（`startup_check.png` 为真实对局画面，1920×1080）。

### 2.3 联调中发现并修复的问题

| 问题 | 原因 | 修复 |
|---|---|---|
| 一直停在加载 logo，30 秒后被判定"离开卫戍协议" | PC 端进入对局要加载 60~90 s，原程序的 30 s 离场保护误杀 | 加载画面（低信息量/含「鹰角网络」「STUDIO」）不计入离场计时；`leave_timeout` 默认改为 90 s |
| 偶发"画面卡住"（OCR 一直是旧画面） | 首选截图方式在切换场景后返回陈旧缓存帧，且程序会永久沿用回退方式 | 新增**陈旧帧检测**：连续相同帧时用其它方式再抓一次，谁给出新画面就切换到谁 |
| 资金读成 6（实际 29） | PC 端资金显示在**顶部状态栏**，安卓版坐标 `GOLD_BOX(1785,768,1850,816)` 位置不对 | 新增 `layout` 坐标覆盖，PC 用 `GOLD_BOX=(1170,20,1265,80)`（实测读到 29） |
| 找不到 MAA 的 OCR 模型 | 目录探测把 MAA 根目录又拼了一次 `resource/PaddleOCR` | 修正 `find_ocr_models`，兼容 MAA 根目录 / PaddleOCR 目录 |
| 中文路径截图失败 / 控制台乱码 | `cv2.imwrite` 不支持中文路径；控制台代码页 936 | 截图改 `imencode` + 二进制写；启动时 `SetConsoleOutputCP(65001)` + `reconfigure` |
| 第二实例与提权实例互相踩 | 提权后新实例被旧实例的命名互斥体挡住 | 提权前先释放互斥体 |

### 2.4 仍存在的已知问题

1. **备战席满时无法购买**：实测买第 4~5 个干员时卡片显示「无法购买」（资金充足、部署位 8 个未满，
   判断为备战席容量受限）。原程序同样只在新干员买到手后才部署，因此连续买满后会被卡住。
   临时建议：先让程序完成部署（等它把备战席上的干员放上场），或手动点「准备就绪」推进一回合。
2. **完整一局未跑完**：联调期间我们主动中断/重开多次（调试用），目标是验证链路而非刷满 3 次角标；
   真正的"连续刷 3 局拿金色角标"还需要一次 15~40 分钟的完整运行验证。
3. **PC 端 UI 与安卓版存在坐标偏移**：商店卡牌中心比原常量偏左约 45 px（在容差内），
   但若后续版本改动 HUD，需要重新校准 `layout`。
4. **鼠标会被程序接管**：点击需要移动真实光标，运行期间用户不应操作鼠标（可开 `block_input`）。
5. 公告/活动弹窗若是独立顶层窗口，PrintWindow 可能截不到（已做活动弹窗合成，
   但极端情况仍需前台截图方式 `screendc`）。

### 2.5 实机复现步骤（建议用户执行）

```bat
:: 1) 打开鹰角启动器进入游戏，停在「卫戍协议」主界面
:: 2) 自检（会弹 UAC 提权）
GarrisonFarmPC.exe --check --probe-tap
:: 3) 看 farm_logs\startup_check.png 是否是游戏画面
:: 4) 先跑一局观察（低配模式不需要自选编队）
GarrisonFarmPC.exe --runs 1 --attempts 1 --profile low --debug
:: 5) 日志里应出现：选择策略 → 自选编队 → 回合N 资金X → 商店升级 → 购买 → 部署 → 准备就绪
```

若第 2 步截图全黑：先确认是管理员运行；仍不行就把 `settings.json` 的
`win32.screencap` 改为 `gdi` 或 `screendc` 再试。
若点击位置有偏移：确认窗口 16:9 / UI 缩放 100%（实测 1920×1080 窗口化时与基准 1:1）。
